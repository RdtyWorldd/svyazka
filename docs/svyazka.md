# Svyazka

Это проект для коммуникации в компании. Связка совмещает в себе почтовый инструмент, 
обмен мгновенными сообщениями и работу над проектами.

## Функуионал проекта

### Почтовый инструмент

Почтовый инструмент позволяет отправлять письма на  электронную почту сотрудника.

### Мгновенные сообщения

Пользователи могут отправлять друг другу мгновенные сообщения. Групповых чатов не предусмотрено.

### Работа над проектами

Работа над проектами представляет собой комплексную структуру, в которой содержатся:
- Темы обсуждений
- Задачи проекта

Темы обсуждений - это групповой чат для всех участников проекта по обсуждению какой-либо проблемы.

Задача проекта - это не полноценный чат, а доска на которой исполнители задачи 
оставляют свои комментарии и прикрепляют материалы.
Задача при создании имеет описание и список исполнителей, которым доступно изменение доски.

## Пользователи

В структуре проекта имеется 3 вида пользователей:
- исполнители
- менеджеры проектов
- администраторы системы

### Общие возможности

Все пользователи системы могут:
- редактировать свой профиль
- отправлять мгновенные сообщения любому другому пользователю системы.
- просматривать историю своих диалогов
- отправлять письма через почтовый сервис
- читать письма, полученные через почтовый сервис
- отвечать на письма, полученные через почтовый сервис

### Возможности Администратора Системы

Администратор системы - это пользователь управляющий учетными записями других пользователей.
Админиминистратор может:
- создавать аккаунт пользователя
- заблокировать пользователя
- изменить роль пользователя
- просматривать журналы создания пользователй
- просматривать журналы отправки писем
- просматривать журналы создания проектов

### Возможности Менеджера Проекта

Менеджер проекта - это пользователй отвественный за выполнение проектов и задач компании.

Менеджер в системе должен уметь:
- создавать проекты
- завершать(архивировать) проекты
- модифицировать структуру проекта
    - добавлять новых участников проекта
    - удалять учатсников проекта
    - создавать темы для обсуждения в проекте
    - завершать(архивировать) темы для обсуждения в проекте
    - создавать Задачи в проекте
    - завершать Задачи проекта с выбором статуса завершения


## Сущности и Модели Данных "Связки"

Основными сущностями свзяки являются:
- пользователи системы
- чаты
- проекты

Ниже изложена модель данных Ксущностей.

### Модель Пользователей

Возможности пользователей системы были описаны в пункте [Пользователи](#пользователи). 
В данной части изложены какие поля должны иметь пользователи и примерное представление в Базе данных и модели приложения.

У пользователя есть 2 основных части аккаунта:
- Системная:
    - Id,
    - Логин,
    - Пароль,
    - Права доступа (Менеджер, Администратор, простой пользователь)
- Бизнесовая:
    - Имя, 
    - Фамилия, 
    - Отчество, по наличию;
    - Подразделение,
    - Должность

### Модель Личных Сообщений

*Чат* личных сообщений это объект внутри которого происходит взаимодейтсвие между двумя пользователями системы.

Чат должен:
- Хранить все отправленные пользователями сообщения
- Хранить вложения
- Предоставлять участникам чата, просмотр вложений

'Чаты' связаны с 'Пользователями' отношениями 'один ко многим'
У одного 'сотрудника' может быть множество чатов, но по одному с каждым другим 'пользователем'.

Таким образом ключем в базе данных может быть объединение (id_user_1, id_user_2)

Каждый чат состоит из множества *сообщений*, все сообщения хранятся в отдельной таблице. 
Сообщение знает:
- Кто его отправил
- В каком чате это произошло
- Текст сообщения
- Прикрепленны ли к нему вложения
- Когда оно создано

Пользователи не состоящие в чате, *не должны* видеть чужие сообщения.

*Вложения* - это сторонние файлы, прикрепленные к сообщению. 
*Пользователь*, может просматривать вложения чата, в отдельной секции.

Вложения имеют несколько базовых категорий:
- Фото
- Документ
- Видео
- Аудио

#### Таблица чатов

Хранит информацию о том какие существуют чаты в системе.

Основные поля таблицы:
- Id чата
- User_1
- User_2
- created_at

#### Таблица 

хранит все сообщения всех чатов, 
вложения хранятся в формате ссылки на таблицу вложений.

Основные поля таблицы:
- Id сообщения
- Id чата
- sender (user_id)
- text (текст сообщения)
- has_attachments
- created_at

### Таблица Вложений

Данные внутри таблицы достаточны, чтобы получить существующий файл с диска.

Основные поля таблицы:
- Id вложения
- Id сообщения
- Id чата (это денормализация, так как многие данные можно получить)
- Type (тип вложения, чтобы было проще искать данные)
- file_name (на первую пору потом заменим)
- object_key (ключ для получения из MiniO)
- created_at
